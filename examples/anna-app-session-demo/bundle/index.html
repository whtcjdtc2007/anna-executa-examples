Best practices for driving anna.agent.session when the agent must read and write workspace files reliably: pin the session to one filesystem client (submode: "fixed"), discover the workspace root and use absolute paths only, verify writes with a nonce read-back instead of trusting completion claims, treat structured filesystem errors (PATH_OUTSIDE_SANDBOX / NOT_FOUND) as a stop signal — never a cue to fall back to a similar path — and classify every terminal state: retry on empty_completion, treat task_cancelled as an outcome, and rely on cancel/delete to really stop runaway runs.

3. Freeform run · cancel · terminal-state handling

Every run ends in exactly one classified state: streamed text · an in-run error frame ({event:"sse", error, error_type} — empty_completion means the model returned nothing and is retried once here, forum /t/191) · a gate error ({event:"error", code}, e.g. queue_timeout) · or task_cancelled. cancel records a signal keyed by run_id: a queued run is dropped before it starts, a running run stops at the next checkpoint — confirm via the stream's task_cancelled + end frames. delete (section 1) also cancels all active runs of the session. In mock mode, send the text EMPTY_COMPLETION_DEMO to see the retry path.

4. Zero-frame recovery · run.status → frames replay

Push pairs with pull (forum /t/341): a silent stream does not mean the run failed — it may have executed and billed server-side while the realtime leg was down. Before re-running, run status (agent.session.run.status) answers queued / running / completed / failed / cancelled for the last run_id; if it completed, replay frames (agent.session.frames) recovers the full output from the archive by seq — no re-run, no double billing. SDK ≥ 0.18.0 also arms this automatically inside run() (firstFrameTimeoutMs, default 20s). Try it: run something in section 3, then use both buttons here.
