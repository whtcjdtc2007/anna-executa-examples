anna-app Long Task Demo

Best practices for tools that outlive the 90-second synchronous ceiling: start them with anna.tools.invokeAsync (returns a jobId immediately — no long-held HTTP request), render live progress via invokeAsyncAwait(…, { onProgress }), cancel with an AbortSignal, and re-adopt the job after a page reload with listJobs({ clientTag }) + getJob({ sinceSeq }).

3. Why not sync? (the 90s ceiling, demonstrated)

      

        The same tool called through plain tools.invoke with a
        150s budget: the platform clamps the wait to 90s and returns a
        structured tool_timeout whose details carry
        requested_timeout_ms / max_timeout_ms. The
        plugin may even finish later — but past the public edge's held-request
        tolerance the result physically cannot reach the browser. That is why
        the async channel exists.
      

      
      

    


    

      Decision table: <90s → tools.invoke · ≥90s or
      "don't block my UI" → tools.invokeAsync. Progress events
      are best-effort (50/s per job, latest 500 kept); the authoritative
      state is always getJob.
