anna-app LLM Demo

Exercises anna.llm.complete (direct, incl. MCP {type:'image'} content blocks for vision models), anna.tools.invoke against an Executa that calls sampling/createMessage (single-shot and an N-step sample_chain that exercises max_calls + sampling-token renewal), and the full agent.session surface (create/run/cancel/history/refresh/delete/list) over both the HOST API and the Reverse RPC transports, including the session lifecycle (sliding idle window, token-free release, resume-by-uuid after reload) and the runtime-accurate tool surface (granted_tools / inherit_host_tools on create + the run_meta first frame with its NO_TOOLS_AVAILABLE warning).

1b. Sample chain (long invoke · token renewal)

Invokes the Executa's sample_chain tool, which fires N sequential sampling/createMessage calls inside a single invoke. This exercises the host's max_calls quota and — with enough steps/delay to outlast the 10-minute sampling-token TTL — the token-renewal path (forum /t/83 "Signature has expired"). Requires the --real LLM bridge; mock fixtures do not serve reverse sampling.

2. Agent session (all methods)

Calls the host session API directly from the iframe.

Applied at create time to every run in this session. A per-run systemPrompt (if passed to run) still wins; the platform safety floor always applies on top.

Session tools (create-time quotaCaps)

Controls the session's tool surface — and therefore the prompt weight: inheriting the full host kit can put hundreds of tool definitions (~100K tokens) in front of every model call, which slows runs down and burns quota. Uncheck to create a sandbox session limited to the listed platform app tools (resolved as: platform public app tools ∩ your user grant ∩ this list; e.g. web_search). An empty list ⇒ text-only agent (no side effects). HOST API transport only — Reverse-RPC sessions are minted via sampling and inherit by default.

Click catalog to discover the platform-tool universe (anna.agent.session.catalog()) — which names are legal here, and per-tool blocked_by diagnostics.

Per-run model preferences (MCP modelPreferences)

Applied to the next run only — sessions do not pin a model. This is a soft preference with the same host-side semantics as llm.complete / sampling: the hint is substring-matched against the platform's active models and falls back to your saved model on a miss — it never fails the run. Forwarded on both transports (HOST API run({modelPreferences}) and Reverse RPC agent/session.run).

Per-run image attachments (native multimodal)

Attach images so the session's model sees them directly in the same inference as your prompt — no upload_local_file → analyze_image tool round-trip. Image MIME types only, max 6 per run; a URL must be public HTTPS. Requires a vision-capable model: a text-only model fails fast with APP_MODEL_NOT_VISION_CAPABLE — pair with the model hint above (e.g. gemini) to pick a vision model. Images are visible for this run only; re-attach if a later turn needs to look again. Forwarded on both transports (HOST API run({attachments}) and Reverse RPC agent_session(op=run, attachments)).

Local files follow the best-practice flow: uploaded first via anna.upload.inline (host storage → short-lived URL), then referenced by url in the attachment — keeping the run payload small and the image reusable across calls. If the upload grant is unavailable the demo falls back to inline base64 data (the host uploads it server-side).
