anna-app Web Search Demo

Demonstrates Anna's host-managed web capability over both channels — the iframe HOST API (anna.web.search / anna.web.fetch) and the Reverse RPC twin (web/search from a bundled Executa). See the host docs (Host API · web.*).

  • Provider keys never leave the host. Routing (tavily → ddgs degrade chain), SSRF guarding, quota, billing and audit are all host-side; results are provider-agnostic. search_depth is a quality intent — the response reports the actually-executed provider_tier and bills the cheaper rate on degrade.
  • HOST API — the iframe calls anna.web.search directly over postMessage. Gated by ui.host_api.web + the per-app web_grant.
  • Reverse RPC — the bundled Executa issues web/search / web/fetch JSON-RPC server requests via its host agent. Gated by host_capabilities: ["web.search", "web.fetch"] + the per-executa web_grant. stdio budgets are tighter (8,000 chars/page, 256 KB/response).

Run with anna-app dev while signed in. The dev install seeds a fully-enabled web_grant on both the app and the bundled Executa (dev calls are never billed). In production the first web.* call returns APP_NOT_GRANTED until the user enables Web access in the app's permission card.
